# kgcache 0.1.0-rc.1

This is the first release candidate for 0.1.0. It is intended for evaluation
while CI and compatibility documentation work continues. The regular 0.1.0
release is still pending.

## Included

- A Redis-protocol-compatible cache with a limited command set, string values,
  multiple databases, expiration, snapshots, and append-only persistence.
- RESP2 connections with command-scoped RESP3 replies selected through `HELLO`.
- Connection metadata through `CLIENT INFO`, filter-free `CLIENT LIST`, and
  `CLIENT SETINFO`.
- A Linux amd64 container image, a built-in health check, and a local Docker
  Compose example.

The required client profiles cover go-redis v9.22.0 and v9.23.0, and node-redis
6.2.0 and 6.2.1. They exercise explicit RESP2, explicit RESP3, and default RESP3
connections. These exact pins describe the tested clients, not a version range.
The release assets include the qualification results for this candidate.

## Known limits

kgcache implements a subset of Redis commands and behavior. It has no
authentication, ACLs, TLS, replication, clustering, transactions, scripting,
pub/sub, RESP3 push messages, tracking, or client-side caching. Use it on a
trusted network. Only Linux amd64 is qualified for this release.

Compatibility documentation and CI follow-up remain before 0.1.0. This includes
scheduled runs of the exact pinned client profiles and a consolidated account
of supported commands, protocol behavior, and test coverage. RESP3 support for
the current command set is already present; broader RESP3 features are outside
this candidate's scope.

This prerelease does not advance the stable Docker line or `latest` aliases.
